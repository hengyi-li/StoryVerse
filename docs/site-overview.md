# StoryVerse 页面、用户旅程与运行说明

> 本文描述当前真实实现。数据库细节见 [architecture.md](architecture.md)，历史变化见 [changelog.md](changelog.md)。

## 1. 页面总览

| 地址               | 页面     | 主要作用                                               | 下一步                                        |
| ------------------ | -------- | ------------------------------------------------------ | --------------------------------------------- |
| `/`                | Gateway  | 产品介绍、故事预览、注册、登录、密保找回、管理员入口   | 新用户进入 StoryStart；回访用户进入草稿或大厅 |
| `/StoryStart`      | 写作入口 | 选择写作引导或自定义入口                               | StoryWrite                                    |
| `/StoryWrite`      | 故事采集 | 正文、年龄、性别、人生阶段、城市、情绪与人物           | StoryAnalyzing                                |
| `/StoryAnalyzing`  | AI 整理  | 服务端安全判断、21 类类型、两个主题与两组向量          | StoryPage 或等待人工审核                      |
| `/StoryPage`       | 故事确认 | 编辑标题/正文/标签，可选生成图片，确认公开             | Resonance                                     |
| `/Resonance`       | 共鸣选择 | 城市、人生、主题分别选择相近或相异                     | StarLobby                                     |
| `/Recommendations` | Top 5    | 查看五则推荐、换一批、互动与举报                       | StarLobby                                     |
| `/StarLobby`       | 星空大厅 | Top 100 三维星图、搜索、故事、账号、通知与再次创作     | 持续使用                                      |
| `/Admin`           | 管理后台 | 真实角色门禁、审核、账号、故事、类型、任务、配置与导入 | 后台操作                                      |

`StoryStart` 到 `StoryPage` 是同一个 `StoryEditor` 的四步体验，而不是四套重复实现。

## 2. 账号流程

### 注册

- 登录账号：4–20 位字母、数字或下划线，不区分大小写。
- 昵称：独立字段，可以使用中文。
- 密码：10–72 位，必须重复确认。
- 密保：从一个问题中选择并填写答案。
- 不需要邮箱、手机号、验证码、邀请码或浏览器旧账号迁移。

前端把用户输入发送到 `auth-signup`。服务端为 Supabase Auth 创建不可见的内部邮箱标识，同时写入 `profiles` 和只存 PBKDF2 哈希的 `account_credentials`。

### 登录与找回

- 登录使用账号 + 密码，错误时统一提示，不泄露账号是否存在。
- 找回使用账号 + 密保问题 + 答案 + 新密码。
- 密保失败不锁定 30 分钟，也不显示剩余次数。
- 账号被管理员停用后不能登录或调用用户接口。

### 管理员

管理员使用普通账号密码。进入 `/Admin` 后，前端登录只是第一步；`admin-api` 还会用数据库角色和账号状态复核权限。仓库中不提供任何演示管理员凭据。

## 3. 新用户旅程

```text
Gateway
→ 注册
→ StoryStart 选择入口
→ StoryWrite 写满 100–1500 字并补齐必填字段
→ StoryAnalyzing
   ├─ 通过：生成类型、主题和向量
   └─ 不确定/失败：转人工，暂不公开
→ StoryPage 确认
→ Resonance 选择共鸣方向
→ StarLobby
```

新账号无论直接输入 `/Resonance`、`/Recommendations` 或 `/StarLobby`，都会被送回故事编辑器。`pending_review` 说明用户已经完成第一篇故事，因此可以进入大厅，但该故事在审核前不会出现在任何其他用户的列表或星空中。

## 4. 写作与故事确认

### StoryStart

- 选择自主能动性、联结、救赎、污损、探索、化解等写作入口。
- 选择“其他”时必须填写自己的入口。
- 引导文案只是创作辅助，不进入安全判断结论。

### StoryWrite

必填项：

- 正文 100–1500 字。
- 年龄 1–120。
- 性别。
- 当时所处的人生阶段：学龄期、青春期、成年早期、成年中期、老年期。
- 城市、情绪、故事人物。

标题可为空，由 AI 给出建议。城市输入先查本地回退表，再通过 Edge Function 调 Open-Meteo。IP 城市建议通过 IPWhois 返回城市、国家和经纬度，不保存完整 IP。正文中的年龄和城市提示只是便捷填写，不是权威数据。

语音输入继续使用浏览器 `SpeechRecognition`。支持程度、是否把音频送到浏览器厂商处理都由浏览器决定；StoryVerse 自己不接收录音。

草稿自动保存到 Supabase；IndexedDB 另保留一个异常恢复副本。新数据使用新的存储版本，不读取旧本地假数据库。

### StoryAnalyzing

服务端豆包一次返回内部机审结果和标签：

- 用户可见结果只有“通过”或“转人工审核”。
- 隐私、攻击、创伤/危险、危机、仇恨、未成年人、露骨、垃圾营销只作为后台类别。
- 不确定、超时、模型请求失败、JSON 格式错误一律转人工。
- 危机内容仍进入同一审核队列，但作者会看到一段温和关怀提示。

安全通过后，AI 必须从 21 类中返回一个类型和两个主题，并生成：

- `story_embedding`：标题 + 正文，1024 维。
- `theme_embedding`：最终两个主题，1024 维。

### StoryPage

用户可以修改标题、正文、类型和两个主题：

- 标题/正文变化：重新安全判断、类型识别与两组向量，旧图片删除。
- 只改主题：只重算主题向量。
- 只改类型：不重算向量。
- 最终主题必须恰好两个；中文 2–6 字，英文 1–3 个词。

可选图片风格只有 3D 粘土、独立杂志、复古拼贴。图片由 Seedream 生成并写入 Storage；每账号每小时最多 5 次，同一故事保留最近 3 张同内容同风格图片。切换风格或修改内容会使旧图片失效。

## 5. 人工审核旅程

```text
机器不确定或失败
→ pending_review（作者可进大厅，故事不公开）
→ 管理员打开
   ├─ 允许公开：补齐标签/向量并 published
   └─ 需要修改：needs_edit + 站内通知
→ 作者修改后重新提交，旧审核案件取消
```

举报会创建或合并到人工审核案件，但故事在管理员决定前继续公开。涉及未成年人安全的案件优先级最高，危机信号其次。普通页面不用“违规、处罚”等强硬文案。

## 6. 推荐和星空

默认参照用户最近一篇已公开且有同版本向量的故事：

```text
城市 15% + 人生 25% + 主题 25% + 正文语义 35%
```

- 城市：经纬度距离衰减。
- 人生：年龄 50% + 人生阶段 30% + 性别 20%。
- 主题：主题向量余弦相似度。
- 正文语义：正文向量余弦相似度，始终正向。
- 城市/人生/主题选择“相异”时使用 `1 - 原分`。

候选只包括其他用户的公开故事，不加入额外多样性重排。推荐页取 Top 5，星空取 Top 100；不足时展示全部。喜欢、不喜欢、举报不改变分数。

没有已审核故事或向量时只显示后台导入的冷启动故事，不使用前端内置假故事。

星空映射：

- 星星距离 = 正文语义分。
- 星星大小 = 正文长度（有限制）。
- 角度/高度 = 故事 ID 的稳定哈希。
- 星星颜色 = 最终 21 类的数据库颜色。

## 7. StarLobby

StarLobby 保留原有 Three.js、React Three Fiber、Bloom、轨道和日夜视觉。用户可以：

- 探索全部推荐、我的故事和喜欢记录。
- 搜索标题、正文、城市、阶段与主题。
- 阅读图片和完整故事。
- 喜欢、点踩或举报。
- 修改共鸣方向；保存后立即生成新推荐批次。
- 修改昵称/密码、提交反馈、读取审核通知。
- 开始下一篇故事或退出登录。

刷新后星点不会随机跳位。管理员下架后，故事不再满足公开查询策略，也不会出现在下一次大厅读取中。

## 8. 管理后台

后台包含八个区域：

1. 人工审核：允许公开 / 需要修改。
2. 账号：查看、停用、恢复、重置密码。
3. 故事：搜索、下架、恢复；不能编辑普通用户正文。
4. 类型：21 类颜色、顺序和启用状态；没有删除入口。
5. AI 任务：查看失败原因和重试。
6. 用户反馈。
7. 推荐权重：保存草稿，再发布版本。
8. 冷启动导入：上传 CSV、按 `external_id` 去重并查看批次结果。

冷启动故事以 `seed_stories` 匿名系统账号发布。CSV 字段：

```text
external_id,title,body,age,gender,stage,city,latitude,longitude,
mood,people,source_note,skip_moderation
```

缺少经纬度时由服务端查询；数据不合法的行写入 `import_failures`，不会让整批回滚。跳过安全审核必须填写授权来源说明。所有后台写操作保留审计记录。

## 9. 路由和状态

项目没有引入 React Router；`src/app/routes.ts` 维护根路径下的 URL 与 `AppState` 映射，并用 History API 同步前进/后退。腾讯云 CloudBase 将 SPA 错误文档配置为 `index.html`，因此深层路径刷新仍返回应用入口，不再保留 `/StoryVerse/` 子路径兼容。

应用级 React 状态只负责当前页面、草稿编辑副本、语言、引导、反应和通知展示。真实会话每次刷新都从 Supabase Auth 恢复，管理员角色不会写入可伪造的持久化状态。

## 10. 视觉与回归

视觉主入口保持不变：

```text
/
/StoryStart
/StoryWrite
/StoryAnalyzing
/StoryPage
/Resonance
/Recommendations
/StarLobby
/Admin
```

`?tour=1` 可重开新手引导。结构清理优先移动数据边界和删除模拟逻辑，不主动改写 Gateway、StoryEditor 或 Three.js 的原有布局参数。每次视觉性改动都应同时检查桌面/移动端、日间/夜间并运行测试与构建。
