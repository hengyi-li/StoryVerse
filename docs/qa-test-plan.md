# StoryVerse 全站 QA 走查与测试方案

版本：2026-08-17  
范围：React/Vite 前端、本地 Supabase、线上 Supabase、Postgres/RLS、Storage、Edge Functions、火山方舟 AI、管理员后台。  
目标：以发现缺陷为目的，逐项触发所有已知业务流程、状态转换、输入边界、权限边界与失败恢复路径。

## 1. 发布门槛

- P0：数据泄露、越权、密钥泄露、故事或图片丢失、无法注册/登录/发布、线上不可用。出现任意一项即阻断发布。
- P1：核心流程错误、错误公开待审内容、推荐/星空核心规则错误、管理员操作不可追溯。出现任意一项即阻断发布。
- P2：局部交互、兼容性、可访问性或明显性能问题。必须有修复决定和回归记录。
- P3：文案、轻微视觉或非阻断优化。允许记录后排期。
- 发布条件：P0/P1 为 0；所有 P0/P1 用例必须实际执行；自动化、浏览器、本地 E2E、线上隔离冒烟全部通过；测试数据清理审计通过。

## 3. 隔离测试数据

- `qa_user_a_*`：普通用户，安全故事、草稿、图片、通知。
- `qa_user_b_*`：第二普通用户，用于 IDOR、推荐、举报和跨用户读取。
- `qa_admin_*`：临时管理员；验证后降权或删除。
- `qa_suspended_*`：停用账号。
- `qa-seed-*`：单条冷启动测试，按本轮唯一 `external_id` 清理。
- `qa_online_*`：线上隔离账号，`finally` 中删除 Storage 文件后删除 Auth 用户。
- 不修改真实用户正文，不使用真实用户故事做写入测试，不删除 `seed_stories` 系统账号。

## 4. 执行顺序

1. 只读基线：工作区、迁移、Functions、故事/图片/队列计数、Storage 一致性。
2. 静态验证：TypeScript、单元测试、数据库测试、生产构建、密钥扫描。
3. 本地接口边界：HTTP、鉴权、RLS、输入、状态机、失败恢复。
4. 本地完整 E2E：注册到大厅、管理员闭环、真实文本/Embedding/图片模型。
5. 浏览器走查：桌面/移动、日夜、中英、键盘、刷新、返回/前进。
6. 线上隔离冒烟：真实 Auth、Functions、Storage、数据库与清理。
7. 缺陷修复后按“失败用例 + 同模块全部 P0/P1 + 主链路”回归。
8. 最终审计：本地 50 条冷启动、线上真实数据、图片与孤儿文件、测试账号残留。

## 6. 浏览器组合

- 主阻断组合：Chromium 桌面 1440×900、Chromium 移动 390×844。
- 兼容组合：Chrome/Edge、Safari；至少覆盖日间/夜间和中/英文。
- 功能差异：语音输入仅在浏览器支持时启用；不支持时必须有降级。
- 3D 场景：WebGL 可用、禁用/失败、窗口缩放、低性能四种路径。

## 7. 缺陷记录格式

每个缺陷必须包含：

1. 缺陷编号、严重度、环境、关联测试 ID。
2. 前置数据和精确复现步骤。
3. 实际结果、期望结果、截图/响应/数据库证据。
4. 根因、修改文件、是否涉及数据修复。
5. 针对性回归结果和可能影响的相邻流程。
